Руководство системного программиста
информационной системы учета заявок на ремонт автомобилей «АвтоТранс»

1. Назначение программы

Программный продукт «АвтоТранс» предназначен для автоматизации учета заявок на ремонт автомобилей в автосервисе. 
Система обеспечивает:
- регистрацию заявок клиентов;
- назначение ответственных автомехаников;
- ведение статусов заявок;
- хранение комментариев по ходу ремонта;
- формирование сводной статистики по работе сервиса;
- резервное копирование базы данных.

Руководство адресовано системному программисту, выполняющему установку, настройку, сопровождение и модификацию программного обеспечения.

2. Состав поставки

В состав программного комплекса входят:
- исходные файлы на языке Python:
  - src\\main.py — точка входа в приложение;
  - src\\config.py — конфигурация интерфейса и общие константы;
  - src\\database.py — модуль работы с базой данных SQLite (создание схемы, CRUD‑операции, резервное копирование);
  - src\\models.py — описания основных сущностей (User, Request, Comment);
  - src\\ui.py — реализация графического интерфейса на библиотеке tkinter;
- файл базы данных SQLite:
  - src\\AutoService.db (создаётся и заполняется при первом запуске);
- файл с блок‑схемами/алгоритмами и текстовой ER‑моделью:
  - src\\block_diagrams.md.

3. Требования к программной и технической среде

Минимальные требования:
- операционная система: Windows 10 или выше;
- установленная среда выполнения Python версии 3.11 (или совместимой);
- объём оперативной памяти: не менее 4 ГБ;
- свободное место на диске: не менее 200 МБ для базы данных и резервных копий.

Необходимые пакеты Python:
- стандартная библиотека (sqlite3, tkinter, dataclasses, typing и др.);
- дополнительные (опционально, для генерации QR‑кода):
  - qrcode
  - Pillow

4. Установка программного обеспечения

4.1. Подготовка окружения
1) Установить Python 3.11 с официального сайта.
2) Убедиться, что путь к python.exe добавлен в системную переменную PATH.
3) При необходимости создать виртуальное окружение (venv) и активировать его.

4.2. Установка дополнительных зависимостей
1) Открыть терминал в корневой папке проекта.
2) Выполнить команды:
   pip install qrcode
   pip install pillow

При отсутствии этих библиотек функционал отображения QR‑кода будет автоматически отключён, основная работа системы не нарушается.

5. Структура данных и база данных

Система использует файломую базу данных SQLite. Путь к файлу определяется константой DB_PATH в модуле src\\config.py.

Основные таблицы:
- Users (пользователи системы, роли и данные для авторизации);
- Requests (заявки на ремонт, статусы, назначенные механики, заказчики);
- Comments (комментарии к заявкам).

Схема таблиц, связи, первичные и внешние ключи, а также индексы подробно описаны в файле src\\block_diagrams.md.

Создание структуры базы данных и заполнение тестовыми данными выполняет модуль src\\database.py (функции init_database и seed_data), вызываемые при запуске main.py.

6. Порядок запуска и завершения работы

1) Открыть терминал в каталоге src.
2) Выполнить:
   python main.py
3) При первом запуске приложение:
   - создаст файл базы данных AutoService.db при его отсутствии;
   - создаст таблицы и индексы;
   - загрузит тестовые данные (пользователи, заявки, комментарии).
4) После закрытия всех окон tkinter процесс приложения завершается автоматически.

7. Описание основных модулей

7.1. main.py
Назначение: точка входа. Выполняет инициализацию базы данных, загрузку тестовых данных и запуск графического интерфейса (форма авторизации).

7.2. config.py
Назначение: хранит параметры конфигурации:
- путь к базе данных DB_PATH;
- цветовую схему интерфейса;
- параметры шрифтов и отступов;
- перечень статусов заявок, типов автомобилей и ролей пользователей;
- URL‑адрес формы обратной связи для QR‑кода.

7.3. models.py
Назначение: содержит dataclass‑модели User, Request, Comment, обеспечивающие удобную работу с сущностями в коде. 
Модели включают служебные методы (например, расчёт длительности ремонта в Request).

7.4. database.py
Назначение: инкапсулирует всю работу с SQLite:
- получение подключения к БД с включённой ссылочной целостностью;
- создание таблиц и индексов;
- загрузка демонстрационных данных;
- функции авторизации пользователя;
- CRUD‑операции по заявкам и комментариям;
- расчёт статистики (количество выполненных заявок, среднее время ремонта);
- создание резервной копии базы данных.

7.5. ui.py
Назначение: определяет все окна графического интерфейса:
- LoginForm — окно авторизации;
- RegisterForm — регистрация нового заказчика;
- MainForm — главное окно (личный кабинет) с различным функционалом в зависимости от роли;
- RequestsForm — список заявок с фильтрами и поиском;
- NewRequestForm — создание новой заявки;
- RequestDetailsForm — просмотр и редактирование подробной информации по заявке, назначение механика, комментарии, QR‑код обратной связи;
- StatisticsForm — окно статистики по заявкам.

8. Резервное копирование и восстановление

8.1. Резервное копирование
Резервное копирование выполняется:
- из пользовательского интерфейса: кнопка «Резервная копия БД» в главном окне для служебных ролей;
- программно: через функцию backup_database в модуле database.py.

Резервная копия сохраняется в папку backup в корне проекта с именем вида:
AutoService_YYYYMMDD_HHMMSS.bak

8.2. Восстановление
Для восстановления БД из резервной копии:
1) Завершить работу приложения.
2) Скопировать нужный файл *.bak в каталог src.
3) Переименовать его в AutoService.db (предварительно сделать копию существующего файла).
4) Запустить приложение заново.

9. Типовые ситуации сопровождения

9.1. Изменение справочников (ролей, статусов, типов авто)
1) Открыть src\\config.py.
2) Изменить соответствующие кортежи:
   - REQUEST_STATUSES;
   - CAR_TYPES;
   - USER_ROLES.
3) Перезапустить приложение.

9.2. Изменение схемы БД
1) Внести изменения в SQL‑команды создания таблиц в функции init_database модуля database.py.
2) При необходимости добавить новые функции выборки/обновления данных.
3) Удалить или переименовать существующий файл AutoService.db (после резервного копирования).
4) Запустить main.py для повторного создания базы по обновлённой схеме.

9.3. Обновление интерфейса
1) Внести изменения в формы в модуле ui.py.
2) При необходимости скорректировать цвета и отступы в config.py.
3) Перезапустить приложение и проверить корректность работы всех ролей.

10. Средства диагностики и отладки

Модуль database.py использует обработку исключений с выводом диагностических сообщений в консоль в формате:
[ERROR] Описание ошибки: <текст исключения>

Рекомендуемый порядок действий при ошибках:
1) Повторить ситуацию и зафиксировать текст сообщения в консоли.
2) Проверить корректность схемы базы данных и наличия файла AutoService.db.
3) При необходимости включить дополнительный вывод отладочной информации (print) в проблемных участках кода.

Для пошаговой отладки рекомендуется использовать встроенный отладчик среды разработки (например, VS Code, PyCharm, Cursor) и точку входа main.py.

11. Порядок внесения изменений

1) Перед модификацией создать резервную копию базы данных.
2) Внести изменения в отдельной ветке системы контроля версий (при её использовании).
3) Обновить при необходимости:
   - блок‑схемы и текстовые описания алгоритмов (block_diagrams.md);
   - настоящие разделы руководства (структура БД, состав модулей).
4) Выполнить функциональное тестирование по заранее описанному протоколу.
5) Зафиксировать версию программного продукта и дату изменения.

12. Ответственность и ведение документации

Системный программист отвечает за:
- поддержание актуальности базы данных и резервных копий;
- корректность настроек окружения и зависимостей;
- актуальность документации (данное руководство, протоколы тестирования, описания модификаций);
- своевременное устранение выявленных ошибок и выполнение регламентных работ по сопровождению.
