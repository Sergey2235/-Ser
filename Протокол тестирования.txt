Протокол функционального тестирования
информационной системы учета заявок на ремонт автомобилей «АвтоТранс»

1. Общие сведения

Цель испытаний: проверка выполнения основных функций системы учета заявок на ремонт автомобилей в соответствии с техническим заданием.
Тестовое окружение:
- ОС: Windows 10;
- Язык программирования: Python 3.11;
- База данных: SQLite (файл AutoService.db);
- Интерфейс: tkinter.

Перед началом тестирования база данных создана и заполнена демонстрационными данными с помощью функций init_database и seed_data.

2. Таблица тестовых сценариев

Формат полей:
- ID теста
- Описание сценария
- Входные данные / шаги
- Ожидаемый результат
- Фактический результат
- Статус (Пройден / Не пройден)

T1. Авторизация с корректными данными
- Входные данные / шаги:
  1) Запустить приложение (python main.py).
  2) В окне авторизации ввести:
     логин: login1
     пароль: pass1
  3) Нажать кнопку «Войти».
- Ожидаемый результат:
  Пользователь успешно авторизуется как «Менеджер». 
  Открывается главное окно личного кабинета с соответствующей ролью и функционалом.
- Фактический результат: соответствует ожидаемому.
- Статус: Пройден.

T2. Авторизация с некорректными данными
- Входные данные / шаги:
  1) Запустить приложение.
  2) Ввести:
     логин: wrong
     пароль: wrong
  3) Нажать кнопку «Войти».
- Ожидаемый результат:
  Отображается сообщение об ошибке «Неверный логин или пароль», повторный запрос учетных данных.
- Фактический результат: соответствует ожидаемому.
- Статус: Пройден.

T3. Регистрация нового заказчика
- Входные данные / шаги:
  1) В окне авторизации нажать кнопку «Регистрация».
  2) Ввести корректные ФИО, телефон, уникальный логин и пароль (дважды).
  3) Нажать кнопку «Зарегистрироваться».
- Ожидаемый результат:
  Появляется сообщение об успешной регистрации.
  Новый пользователь с ролью «Заказчик» добавлен в таблицу Users.
- Фактический результат: соответствует ожидаемому.
- Статус: Пройден.

T4. Регистрация с незаполненными обязательными полями
- Входные данные / шаги:
  1) Открыть окно регистрации.
  2) Оставить одно или несколько обязательных полей пустыми.
  3) Нажать кнопку «Зарегистрироваться».
- Ожидаемый результат:
  Появляется предупреждающее сообщение о необходимости заполнить все поля.
  Пользователь не создается.
- Фактический результат: соответствует ожидаемому.
- Статус: Пройден.

T5. Создание новой заявки
- Входные данные / шаги:
  1) Войти под пользователем с ролью «Оператор» или «Менеджер».
  2) Перейти в раздел «Заявки».
  3) Нажать «Добавить заявку».
  4) Выбрать клиента, тип автомобиля, ввести модель и описание проблемы, при необходимости выбрать механика.
  5) Нажать «Сохранить».
- Ожидаемый результат:
  Появляется сообщение об успешном создании заявки с присвоенным ID.
  Новая заявка отображается в списке заявок со статусом «Новая заявка».
- Фактический результат: соответствует ожидаемому.
- Статус: Пройден.

T6. Попытка создания заявки с незаполненными полями
- Входные данные / шаги:
  1) Открыть форму создания заявки.
  2) Не заполнять модель автомобиля или описание проблемы.
  3) Нажать «Сохранить».
- Ожидаемый результат:
  Появляется предупреждающее сообщение о необходимости заполнить соответствующее поле.
  Заявка не создается.
- Фактический результат: соответствует ожидаемому.
- Статус: Пройден.

T7. Изменение статуса заявки и расчет даты завершения
- Входные данные / шаги:
  1) Войти как «Менеджер» или «Оператор».
  2) Открыть существующую заявку со статусом «В процессе ремонта».
  3) В деталях заявки установить статус «Готова к выдаче».
  4) Нажать «Сохранить статус».
- Ожидаемый результат:
  Статус заявки изменяется на «Готова к выдаче».
  В базе данных в поле completionDate автоматически устанавливается текущая дата.
  В форме деталей отображается длительность ремонта в днях.
- Фактический результат: соответствует ожидаемому.
- Статус: Пройден.

T8. Добавление комментария к заявке
- Входные данные / шаги:
  1) Войти как «Автомеханик» или служебная роль с правом доступа к заявке.
  2) Открыть детали конкретной заявки.
  3) Ввести текст комментария в поле «Новый комментарий».
  4) Нажать «Добавить».
- Ожидаемый результат:
  Комментарий сохраняется и отображается в списке комментариев с указанием автора и даты.
- Фактический результат: соответствует ожидаемому.
- Статус: Пройден.

T9. Расчет количества выполненных заявок и среднего времени ремонта
- Входные данные / шаги:
  1) Войти как «Менеджер» или «Менеджер по качеству».
  2) Перейти в окно «Статистика».
- Ожидаемый результат:
  Отображаются корректные значения:
  - общее количество заявок;
  - количество выполненных заявок (статус «Готова к выдаче»);
  - количество активных заявок;
  - среднее время ремонта в днях (либо сообщение об отсутствии завершенных заявок).
- Фактический результат: соответствует ожидаемому.
- Статус: Пройден.

T10. Резервное копирование базы данных
- Входные данные / шаги:
  1) Войти как «Оператор», «Менеджер» или «Менеджер по качеству».
  2) В главном окне нажать кнопку «Резервная копия БД».
- Ожидаемый результат:
  В каталоге backup создается новый файл резервной копии AutoService_YYYYMMDD_HHMMSS.bak.
  Отображается сообщение об успешном создании резервной копии. При ошибке — информативное сообщение об ошибке.
- Фактический результат: соответствует ожидаемому.
- Статус: Пройден.

3. Выводы по результатам тестирования

По результатам выполнения тестовых сценариев T1–T10 все проверенные функции системы работают в соответствии с ожидаемым поведением.
Критических сбоев и потери данных не выявлено.

- регулярно проводить регрессионное тестирование после внесения изменений в код.
